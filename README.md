# SillyTavern Manager

**SillyTavern Manager（STM）** 是一个 SillyTavern 管理器。

STM 希望让用户像管理容器一样管理不同版本的 SillyTavern：安装、启动、停止、切换和恢复由统一界面处理，SillyTavern 本身则尽可能保持接近官方上游。

> STM 是独立实现的第三方项目，不是 SillyTavern 官方项目，也不隶属于 SillyTavern 项目团队。

## 产品优势

- **接近官方上游**：以官方 SillyTavern 为运行主体，不重写其核心业务。
- **版本相互隔离**：不同版本使用独立、不可变的运行槽位，程序与用户数据分离。
- **升级可以回退**：新版本安装失败时保留原有可用版本，为切换和恢复提供基础。
- **原生管理体验**：通过平台原生界面管理下载、安装、运行状态、日志和应用文件。
- **本机私有运行**：SillyTavern 运行服务只向应用内的本机回环地址提供服务。
- **安装过程可验证**：日常安装验证签名归档并完成可运行验收；需要排障时可主动执行完整槽位校验。
- **兼顾易用与自主性**：优先使用版本绑定、经过签名验证的预构建运行层快速安装；无法获取时由用户选择重试或明确启动较慢的设备本地构建。

## 当前进度

当前版本为 **v0.0.4 开发预览版**。

Android 版本已经打通下载、验证、安装、启动、停止和打开 SillyTavern 的基础闭环。普通界面以用户命名的 ST 实例为中心，同一官方版本可以分别安装成多个独立实例；每个新实例都使用自己的 READY 程序槽与用户数据目录，不复制其他实例中可能已经修改的程序树。

STM 打开后，Core 会进入私有后台进程待机，但不会自动启动 SillyTavern。用户启动 ST 后，本机服务会在切换 STM 页面期间持续运行，并通过 Android 前台服务通知保持可见；用户停止 ST、关闭 Core，或真正结束 STM 任务时，Core 会按顺序优雅停止运行会话。

首页只保留 Core 健康与当前 ST 实例的常用启停入口；启动成功后自动进入真实 SillyTavern 页面。侧边栏中的“ST 后台”显示 SillyTavern 原生后端输出，STM 自身的 Core 状态、维护任务和诊断导出则收纳在设置中的高级入口。

当前开发版已接入 SillyTavern 1.18.0 正式版的候选快速安装路径：运行层从 STM 的 GitHub Release 单独下载，下载时一次性核对长度与 SHA-256，并验证签名、上游 commit、lockfile、运行时和许可证绑定。安全解压仍会拒绝危险路径、特殊文件、超限内容和 CRC 错误；随后在设备 staging 中启动 SillyTavern 完成可运行验收，最后才提交不可变运行槽位。日常安装、启动和恢复不会自动逐文件重算完整槽位摘要，用户可以在版本管理页主动运行“完整校验”进行故障诊断。STM 只为正式版发布预构建运行层；预览版不建议普通用户使用，安装时必须由用户明确确认约 10 分钟的设备本地 npm 与 `lib.js` 构建。正式版 Release 无法获取或没有精确匹配的运行层时，STM 会停止并提示用户检查网络、重试，或在了解耗时与资源开销后明确选择本地构建；已下载但校验失败的运行层不能通过本地构建绕过。

目前仍在完善安装恢复、异常中断处理和跨设备兼容性。项目尚未发布稳定版，不建议作为唯一的生产环境使用。

当前支持范围：

- Android 12 及以上；
- ARM64（`arm64-v8a`）设备；
- 简体中文和 English 界面。

## 构建

需要 JDK 17 和 Android SDK 36。

```bash
./gradlew assembleDebug
```

运行单元测试和 Android Lint：

```bash
./gradlew testDebugUnitTest lintDebug
```

调试 APK 输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 项目结构

- `app/`：当前 Android 应用、原生界面和管理功能；
- `stm_core/`：SillyTavern 运行、安装、槽位和恢复能力。

第三方源码、研究资料、私人配置、密钥、签名文件和构建产物不属于本仓库。
